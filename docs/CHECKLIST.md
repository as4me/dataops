# Чеклист готовности к сдаче

Отметьте пункты перед защитой проекта. Без отмеченных **обязательных** пунктов проект к зачёту не допускается.

## Обязательный минимум

- [ ] Минимум 3 типа источников данных (например: PostgreSQL / REST API / CSV)
- [ ] Автоматизированный Data Pipeline
- [ ] Оркестрация (Airflow DAG или аналог)
- [ ] Слой RAW
- [ ] Аналитический слой (MART), минимум 3 витрины
- [ ] Минимум 10 Data Quality Tests
- [ ] Git-репозиторий с историей изменений
- [ ] CI pipeline (GitHub Actions / GitLab CI / аналог)
- [ ] Базовый мониторинг / observability
- [ ] Data Lineage (хотя бы для одного показателя)
- [ ] README с полным описанием
- [ ] Итоговый аналитический результат (dashboard / представления)
- [ ] Презентация к защите

## Инфраструктура и воспроизводимость

- [ ] `docker compose up` (или эквивалент) поднимает сервисы
- [ ] Секреты не хранятся в Git (используются `.env` / secrets)
- [ ] В README есть пошаговая инструкция запуска с нуля
- [ ] Сторонний пользователь может воспроизвести запуск

## Ingestion

- [ ] Загрузка из всех заявленных источников
- [ ] Фиксируются `ingestion_timestamp`, источник, объём записей
- [ ] Есть обработка ошибок
- [ ] Повторный запуск идемпотентен (без неконтролируемых дубликатов)

## Моделирование (dbt)

- [ ] STAGING: типы, очистка, переименования
- [ ] CORE: dim / fact
- [ ] MART: минимум 3 витрины
- [ ] Используются `ref()` и `source()`
- [ ] Модели задокументированы

## Качество данных (покрыть разные измерения)

- [ ] Completeness
- [ ] Uniqueness
- [ ] Referential Integrity
- [ ] Validity
- [ ] Freshness
- [ ] Business Rules

## CI/CD и Git

- [ ] Работа через ветки и Pull Request
- [ ] CI запускается на PR
- [ ] При критической ошибке pipeline = Failed
- [ ] Нет прямых коммитов в production-ветку (или это обосновано)

## Observability и надёжность

- [ ] Отслеживается успешность / длительность pipeline
- [ ] Отслеживается объём данных и аномалии
- [ ] Определены минимум 1 SLA и 1 SLO

## Аварийные сценарии (демонстрация на защите)

- [ ] Сценарий 1: ошибка качества (orphan FK)
- [ ] Сценарий 2: нарушение freshness (нет файла)
- [ ] Сценарий 3: schema change → fix → PR → CI → восстановление

## Аналитика

- [ ] Revenue, Orders, AOV, Active Customers
- [ ] Return Rate, Top Products
- [ ] Revenue by Category, Revenue Dynamics
  (или свой набор с бизнес-обоснованием)

## Документы на сдачу

- [ ] Ссылка на Git-репозиторий
- [ ] Архитектурная схема
- [ ] README
- [ ] Презентация
- [ ] (Опционально) запись демо pipeline / dashboard
