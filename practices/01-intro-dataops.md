# Практика 1. Введение в DataOps

**Лекция:** [01-introduction-to-dataops.md](../lectures/01-introduction-to-dataops.md)  
**Время:** 60–90 мин  
**Цель:** зафиксировать боли «традиционной» аналитики и сопоставить их с принципами DataOps.

---

## Подготовка

Репозиторий проекта ещё можно пустой. Нужны: Git, Markdown-редактор.

---

## Задание A. Аудит «как было бы без DataOps» (30 мин)

Опишите вымышленный (или знакомый) процесс отчётности интернет-магазина **без** DataOps.

В файле `docs/practice-01-as-is.md` заполните таблицу:

| Боль | Как проявляется | Кто страдает | Как ловят ошибку сейчас |
|------|-----------------|--------------|-------------------------|
| Ручная загрузка | … | … | … |
| Нет версий SQL | … | … | … |
| … | | | |

Минимум **6 болей** из лекции 1.3.

---

## Задание B. Карта принципов (20 мин)

Для каждой боли из A укажите **принцип DataOps**, который её закрывает (1.7 / манифест).

Пример:

```text
Нет версий SQL → Data as Code + PR/Review
Ошибки в отчёте → Shift-left / Data Quality tests
```

---

## Задание C. Сравнение DevOps / DataOps / MLOps (15 мин)

Нарисуйте (Mermaid или таблица) один бизнес-кейс магазина и отметьте:

- что относится к DevOps (сайт/API заказов);  
- что к DataOps (витрины, пайплайны);  
- что к MLOps (если появится рекомендательная модель).  

---

## Задание D. Мини-манифест команды (15 мин)

Напишите 5 правил вашей учебной команды в духе DataOps Manifesto, например:

1. Неправим prod SQL без PR.  
2. …  

Сохраните в `docs/team-dataops-rules.md`.

---

## Критерии готовности

- [ ] Таблица ≥6 болей  
- [ ] Каждая боль связана с принципом  
- [ ] Есть сравнение DevOps/DataOps/MLOps  
- [ ] Есть 5 командных правил
